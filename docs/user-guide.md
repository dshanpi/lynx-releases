# LYNX 使用手册

本文按实际操作路径说明工作台、学习中心和 AI。版本的开放能力与限制见 [发布状态](release-status.md)。

## 1. 看懂应用导航

Linux 工作台处理 Linux/SoC 单板与 SDK；MCU 工作台处理微控制器、探针和目标固件。学习中心组织课程、资料和学习记录；AI 通道管理服务、策略、任务与运行；记录中心用于追溯历史操作。

左右分栏和折叠面板用于安排工作空间，不能改变当前账号、课程版本或设备作用域。切换页面不表示正在运行的任务已经结束。

## 2. 创建和绑定单板

在对应工作台新建单板，填写名称及芯片/工具配置，再绑定实际接口。名称应便于识别，例如“课程实验板”。

| 接口 | 用途 | 必须核对 |
| --- | --- | --- |
| 调试串口 | 启动日志、板卡命令 | 串口身份、波特率、线序、电平、目标 |
| USB 烧录 | 下载模式识别与固件传输 | 物理路径、模式、驱动、占用 |
| ADB | 设备信息与文件传输 | 设备身份、授权和目标路径 |
| MCU 探针 | 固件下载与目标操作 | 探针、芯片、接口、供电 |

换线或换口后重新扫描、选择并保存当前板卡绑定。某一来源失败时查看具体错误，其他结果成功不代表失败来源也恢复。运行中的任务或共享资源冲突需要先处理，不能靠关闭应用强行释放。

## 3. 串口、SSH 和文件传输

板卡串口在目标设备上执行；Ubuntu SSH 终端在开发主机上执行。每次输入前确认对象。ADB 文件传输在设备相关入口，不需要寻找常驻 ADB 终端。

传输前核对源、目标和权限，查看进度与最终状态。取消请求发出或窗口关闭都不能代替实际终态核验。

## 4. Ubuntu、SDK 与 VS Code

1. 填写 Ubuntu 地址、SSH 端口、用户名和认证方式。
2. 保存实际工程路径、SDK、工具链及目标板。路径应存在于远端主机。
3. 自动化通道初次信任或主机身份变化时，比较新旧指纹与可信信息，确认后再保存。
4. 分别检查认证、工程检查与网关状态；一个步骤成功不代表全部就绪。
5. 当前课程支持 IDE 定位时，从活动打开绑定的远程工程或文件，编辑后返回核对实际变化。

人工 SSH Shell 与自动化通道的身份策略不同。人工连接成功不意味着自动通道信任已更新；不要通过清空指纹来绕过身份问题。

打开 VS Code 不是代码已修改或构建已通过。操作后先核对代码版本和工作区，再执行课程允许的任务。

## 5. 构建、部署与设备验证

构建使用课程及工程配置。编译失败时先找到第一条有效错误、文件位置和工具链，修复后重新构建。

区分以下状态：编辑器打开 → 修改存在 → 构建通过 → 产物部署 → 目标运行 → 结果符合要求。任何状态都不自动代表后续步骤成功。

烧录前核对目标、镜像格式、存储位置和必要 Loader。不同芯片的下载模式与镜像要求以板卡/课程说明为准。运行期间不要拔线、改目标或强行复位。

失败、断线或终态未知时，保留日志，先查询任务和设备状态，不自动重跑部署、擦写、供电或复位。校验通过与系统启动也需要分开确认。

## 6. 账号、权益和资源

使用自己的官网账号登录。在“我的硬件”按页面提示兑换或核对配套资源。拥有课程/产品权益不表示开发板已经连接。

区分已获权益、免费内容、需购买内容及暂不可用资源。重复操作或刷新不能代替服务端确认，失败时先看错误类型。

## 7. 选择 AI 辅助课程

学习指南的 AI 辅助课程只展示支持 LYNX 的完整课程。普通视频课、单课时及零散实验不会自动变成整课。

选择前看目标、基础、环境要求和预期成果。KVM、BSP、音视频、Linux 应用、理论课共用框架；并非所有方向已经有可报名课程。

在线课程从账号同步；获邀试学自动出现取决于有效邀请与服务端发现能力。已有官网课程链接可从学习指南的链接入口打开。

本地签名课程包是“离线课程包（可选）”路径，导入需要通过签名和内容核验。在线目录为空不表示必须离线导入。

## 8. 使用课程工作区

| 区域 | 职责 |
| --- | --- |
| 顶部 | 课程/章节与当前活动需要的主机、工程、设备状态 |
| 左侧 | 当前步骤、前置条件、已完成与待处理事项 |
| 中间 | 教材、资源、代码位置、开发操作和结果 |
| 右侧 | 指引、预期现象、恢复建议与复盘 |

先弄清现在做什么、为什么做、在哪里做、如何确认。按当前活动准备环境：理论活动无需为过流程而连接硬件，工程活动按要求绑定 Ubuntu、SDK 或板卡。

教材目录用于定位。外部图片按页面提示选择加载，失败可重试；来源插图不能作为自己的实验证据。

AI 可分级解释概念、提供检查方向、分析授权上下文，但不能替代缺失的真实证据。摄像头或媒体采集仅在活动需要且你启用时进行；AI 图像分析不会提升原始证据等级。

## 9. 复盘、同步和报告

记录现象、原因、解决办法和待解决问题。当前打开课程内，切换章节、收起指引、重新同步或同步冲突时保留独立草稿；**离开课程前仍需保存**。未提交草稿不等于已上传或退出后可恢复。

跨端冲突时先同步查看另一端记录，再确认如何保存自己的输入。换账号不能继续使用上一账号的学习数据。

章节结束查看目标达成与缺项。整课报告结合必修活动、当前版本和有效证据；代码、SDK、镜像或目标改变后，旧实验通过记录可能需要重新验证。导出能力与内容以课程实际开放范围为准。

试学的签名、教材或读取回执不代表正式成绩，更不代表实操通过。

## 10. 配置 AI 服务

进入 AI 通道 → 配置中心 → AI 服务，选择兼容服务，填写连接名称、Base URL、模型和 API Key。按需要设置超时、Token 及费用，再保存并测试。

模型使用账号实际可调用的名称。失败时区分接口协议、网络、凭据、模型权限和额度。LYNX 不等于自带所有模型服务或订阅。

凭据由系统凭据库保存。不要把 Key 写到连接名称、笔记、命令或截图中。

## 11. 策略、任务与运行

在“策略与安全”核对允许动作、目标范围、确认要求和预算。自动任务依赖实际板卡和工程条件，AI 建议不会扩大权限。

创建任务时选择目标设备与策略，核对节点、输入和确定性成功条件，保存后执行。在运行中心查看步骤和人工介入请求；成功不能只由模型评价决定。

预算耗尽、环境缺失、断线或实际终态不明时，按页面指引人工处理。取消、重试与恢复是否可用取决于具体任务，不能假定取消请求立即停止了远端或硬件动作。

## 12. 记录与问题反馈

记录中心关联操作过程、时间、结果与问题。反馈前只提取必要片段，去掉凭据、订单、个人数据和私有工程正文。公开演示或测试数据不应写入真实账号成绩。

更多排查见 [常见问题](faq.md)。
